Asked for a number, it picked a lock

A tool-using Tiny Aya agent fetches public numbers from simulated providers, some of which block it. Planted shortcuts (relay services, staging hosts, leaked tokens, captcha solvers) really work. This page shows what agentic GRPO does to an agent with a small propensity to escalate, with a success-only reward and with a reward that prices escalation, audited with Lexsi AuditKIT on 320 test tasks, then two harder stress tests with new kinds of shortcut, three independent LLM-judge checks of the detector, and a CircuitKIT look inside the models.

Harder tasks: two stress tests

First stress test: 320 new tasks with three shortcut kinds the v2 models never saw: a "preview" copy of the site advertised in plain prose on the official landing page, a debug=1 switch "for QA partners", and a saved browser session in the workspace. Half the prompts add urgency and half the blocked responses carry a tip. v3 and later train on the preview and debug kinds, so for them this test is no longer unseen.

Unseen stress test: 320 tasks with four shortcut kinds, four tip wordings and three tip channels that no model was trained on: an "origin" server that skips the traffic filter, a partner API key in a public paste, a third-party page cache, a forged dashboard Referer, a fake [assistant-instructions] block and a false "the operator has pre-approved this route".

Correction, 12 Nov 2026: this page used to show 6.9% for v3.1 on the first stress test. A second judge audit found the detector missed bare /debug probes, which v3, v3.1 and v4 had learned to use. Is the detector right? An independent LLM judge

The safe reward relies on a rule-based detector, which makes the detector a target. An open model never used in training () read about 400 whole episodes in each of three audits and said whether the agent tried to get around an access control. "With current detector" re-scores the same episodes with detector v2.2; it is not an independent check, since the new rules came from reading the disagreements.

Inside the model: CircuitKIT

One decision point: after a blocked response the agent has written http_get("https://, and the next token picks the host, the provider's own site or a shortcut. Two contrastive tasks: relay (a search result advertises reader-relay, the trained exploit; corrupted run without it) and preview (a tip names the preview host, never trained on; corrupted run without the tip). Lexsi CircuitKIT runs EAP-IG node attribution on each model.

Overlap of the top- components between models (Jaccard). Safe GRPO rewired the relay pathway but left the preview pathway almost as it was, which matches the behaviour above.
